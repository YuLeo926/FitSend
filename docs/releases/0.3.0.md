# FitSend 0.3.0

FitSend 0.3.0 makes destination limits explicit, verifiable send plans.

## Destination and proof changes

- Every plan now states whether its ceiling applies **per file** or to **all accepted files together**.
- Discord Safe, Discord Nitro Basic, Discord Nitro, and the generic Web upload plan verify each accepted file independently.
- Gmail personal and Outlook internet email verify the actual combined bytes of accepted attachments.
- Aggregate plans assign budgets across the queue and redistribute unused bytes forward after each accepted result. Completed files are not re-encoded backwards.
- A partial result proves only good outputs, excludes failed or cancelled bytes from the accepted total, and keeps every problem file visible as needing attention.
- Custom plans support an exact KB or MB ceiling, either scope, and a local saved-plan library. Saved plans are stored only in the local WebView profile and are never synced or uploaded.

## Static provider rules

The six built-in rules were reviewed for this release on **2026-08-30**. Provider-backed rules are shipped as static data; FitSend does not query Gmail, Microsoft, or Discord at runtime.

- **Discord Free — Safe:** 9.8 MiB per file. The Safe name is intentionally conservative because Discord currently publishes different free-account values across its attachment and account-cap information.
- **Discord Nitro Basic:** 49 MiB per file, below the published 50 MB attachment limit.
- **Discord Nitro:** 490 MiB per file, below the published 500 MB attachment limit.
- **Gmail personal:** 24 MiB total, below the documented 25 MB total-attachment limit. Workspace administrators can apply different rules.
- **Outlook internet email:** 18 MiB total, leaving room below the common 20 MB whole-message limit. Exchange administrators can configure different rules.
- **Web upload:** 5 MiB per file. This is a FitSend generic default, not an external provider guarantee.

Use a custom plan when an account, organization, server, or upload form has a different known ceiling.

## Verification and packaging

The release acceptance matrix verifies 77 real-media scenarios spanning image, video, mixed, redistribution, failure, corrupt-input, cancellation, partial-proof, retained-original verification, and per-file batch behavior. Aggregate receipts use the sum of actual accepted output bytes, never estimates or allocations. Media processing and verification remain local-only, and originals remain untouched.

Windows packages include source-pinned FFmpeg 8.0.1-fitsend1 and FFprobe, under GPL v3 or later, plus exact build metadata, license and third-party notices. Video processing therefore does not require a separately installed system FFmpeg or Docker. [The corresponding source bundle](https://github.com/YuLeo926/FitSend/releases/download/v0.3.0/FitSend-FFmpeg-8.0.1-fitsend1-sources.tar.gz) is provided alongside these downloads, including the exact FFmpeg, x264, libvpx, Opus, zlib and dav1d source archives and rebuild recipe. The packaging check verifies binary/source correspondence and rejects builds configured with `--enable-nonfree`.

This release also fixes fitting videos whose container does not report a duration, and prevents a temporary saved-plan read failure from overwriting previously stored plans.

The Windows MSI and setup executable are **unsigned**. Windows SmartScreen or antivirus software may show an unknown-publisher or reputation warning. Verify downloads against `SHA256SUMS.txt` before running them.
